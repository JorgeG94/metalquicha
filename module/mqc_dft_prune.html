prune_angular_orders

Angular pruning: fewer Lebedev points where the density does not need them

An unpruned grid uses the same Lebedev order at every radius, which is wasteful at both ends. Very close to a nucleus the density is nearly spherical, so a high-order sphere resolves nothing; very far out it is almost gone. Pruning drops the order in those regions and keeps it in the valence shell where the structure is.

The NWChem scheme divides each atom’s radial range into five zones by r/R_bragg, with thresholds depending on whether the element is H/He, second row, or heavier, and assigns orders

50, 86, one below the target, the target, one below the target

reading outwards. It is what PySCF uses by default, so a pruned grid here can be compared against a pruned grid there point for point.

Pruning changes the answer – it is an approximation, not a reorganisation. What it must not change is the answer beyond the accuracy the grid claims, which is what the validation checks.
