The atomic radii the program uses, gathered so that a caller picks a parametrisation deliberately instead of finding whichever table happened to be nearest.

There is no single “atomic radius”. These tables disagree with each other by tenths of an Angstrom because they were fitted to different things, and swapping one for another silently changes results. So they are kept apart and named for their source rather than merged into a default:

Accessor Source Fitted for
covalent_radius_cordero Cordero (2008), Z <= 96 bond perception
covalent_radius_emsley Emsley, as GAMESS, Z <= 36 DMA bond midpoints
vdw_radius_bondi Bondi/Mantina, Z <= 18 PCM cavity
vdw_radius_geodesic GAMESS geodesic, Z <= 17 ESP screening grid

The Bragg-Slater radii that size the DFT partition cells are deliberately not here: they live in mqc_dft_radial_data, which is generated by tools/dft_grid/gen_radial_fortran.py and would be rewritten by the next regeneration. Reach them through mqc_dft_radial’s bragg_radius.

Every accessor returns Angstrom and reports an unknown element rather than substituting a number, because for all four of these an invented radius shows up as an invented bond or an invented cavity rather than as an error. Covalent radii in Angstrom, Emsley’s table as GAMESS uses it, indexed by Z.

A bond is |Ri - Rj| <= rad_i + rad_j, evaluated in Angstrom, which is what decides where the bond midpoints go and therefore how many expansion points there are. Only through the first two rows plus the common heavier atoms – anything beyond is refused, because silently inventing a radius would silently invent or drop a bond.
