# Starting a session on metalquicha

What a fresh session needs to get from an empty container to a working build,
tests and timings, plus the conventions that are easy to get wrong. `AGENTS.md`
(loaded through `CLAUDE.md`) is the project guide and wins where the two
disagree; this file is the operational checklist that sits beside it.

## 1. Toolchain

The "metalquicha" cloud environment's setup script installs all of this. A
container that started bare, or was replaced, needs it again:

```bash
apt-get update -qq
DEBIAN_FRONTEND=noninteractive apt-get install -y -qq gfortran libopenblas-dev liblapack-dev pkg-config
pip install -q fortitude-lint==0.9.2 fprettify pre-commit
python3 -m pip install -q --ignore-installed packaging pyscf
```

- `gfortran` from apt is 13, which is supported; CI uses 14.2 from conda.
- fortitude is pinned to **0.9.2** because CI pins it; 0.10 reports ~1500
  findings CI does not.
- **PySCF must be installed with `python3 -m pip`.** Plain `pip` here installs
  for a different interpreter than `python3`, and Debian's `packaging` blocks the
  upgrade PySCF asks for, hence `--ignore-installed packaging`. Check with
  `python3 -c "import pyscf; print(pyscf.__version__)"`.
- NEO references need Yang Yang's fork: https://github.com/theorychemyang/pyscf
  (`pyscf/neo`; see `mqc_docs/source/neo.rst`).
- `perf` for profiling: `apt-get install -y linux-tools-common linux-tools-generic`,
  then use `/usr/lib/linux-tools/*/perf` (the `perf` wrapper on the PATH looks for
  the running kernel's version and does not find it). `perf_event_paranoid` is 2
  in the cloud containers, which is enough for your own processes.

## 2. Build

```bash
cmake --preset default -G Ninja -DMQC_ENABLE_TBLITE=OFF -DMQC_ENABLE_MPI=OFF
cmake --build build -j4
```

- tblite off makes the build much faster; MPI off avoids needing an MPI
  install. Drop either flag when the task needs it (MPI also needs
  `libopenmpi-dev`).
- The first build fetches and compiles libxc, libfint and the rest: about 2,300
  steps, tens of minutes on 4 cores. Run it in the background. Later builds only
  recompile what changed.
- A cached `MQC_LIBFINT_TAG` survives a reconfigure. To move libfint versions,
  add `-UMQC_LIBFINT_TAG -UFETCHCONTENT_SOURCE_DIR_LIBFINT`.
- Release is `-O3 -march=native`; there is no `-ffast-math`.

## 3. Tests and validation

```bash
ctest --test-dir build -R mqc -LE LONG -j4 --output-on-failure     # what CI runs
ctest --test-dir build -R "<regex>" -LE LONG -j3                   # a subset
cd validation && python3 run_validation.py --manifest validation_tests_cpu.json -t <substring>
```

- Tests labelled `LONG` (and the benchmarks) take 30 minutes or more; leave them
  out unless the change touches what they cover.
- **Validation runs from inside `validation/`**: every default path is relative.
- **Skips print green.** A build without tblite skips most of the default
  manifest. Read the "Total tests" line, not the colour. `validation_tests_cpu.json`
  is the manifest that exercises a build without tblite.
- Categories are the directories under `validation/inputs/cpu/mqc/` (dft, udft,
  df-dft, df-hf, tddft, gradient, hessian, dh, fmo, pcm, soscf, ...). The CPU
  suite is generated by `tools/cpu_validation/gen_cpu_validation.py`; never add a
  deck by hand under `cpu/mqc/`.
- References are PySCF fed this repository's basis JSON (`basis_sets/`), not
  PySCF's own tables. PySCF 2.15 does **not** prune the DFT grid by default
  (`small_rho_cutoff = 0`), so the references are unpruned.

## 4. Running and timing

```bash
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 ./build/mqc deck.json
tools/run.sh -n 4 deck.json            # sets the BLAS threads for you
```

- **Always hold the BLAS to one thread** (`OPENBLAS_NUM_THREADS=1`, or
  `MKL_NUM_THREADS=1`). The XC quadrature calls the BLAS from inside its own
  OpenMP threads; a threaded BLAS fights them and the quadrature stops scaling.
- Verbosity is in the deck, never on the command line:
  `"system": {"logger": {"level": "verbose"}}`. At verbose an SCF prints its
  timing table, the XC quadrature breakdown (basis evaluation, density, libxc,
  potential assembly, in thread-seconds), the basis functions per grid block,
  and the density-fitting timings.
- The SCF energy tolerance key is `keywords.scf.tolerance`
  (`energy_tolerance` is refused by the schema).
- Repeat a timing at least three times and take the median. Do not time while
  a build or a test run is using the cores; check `uptime` first.
- Profile: `perf record -F 999 -e cpu-clock -o x.perf -- <cmd>`, then
  `perf report -i x.perf --no-children --sort symbol --stdio` (and
  `--sort dso` to split mqc / BLAS / libxc / libm).

A water-cluster deck for DFT timing (PBE/def2-SVP, RI-J, grid level 3 -- the
setup of the DFT benchmark this work has been compared against):

```json
{
  "schema": {"name": "w10-pbe", "version": "1.0"},
  "molecules": [{"xyz": "w10.xyz", "molecular_charge": 0, "molecular_multiplicity": 1}],
  "model": {"method": "DFT", "basis": "def2-svp", "aux_basis": "def2-universal-jfit",
            "cartesian": false, "functional": "pbe"},
  "keywords": {"scf": {"density_fitting": true, "tolerance": 1e-7},
               "dft": {"grid_level": 3}},
  "system": {"logger": {"level": "verbose"}},
  "driver": "Energy"
}
```

On that benchmark's own 10-water geometry, PySCF gives -762.843593 Eh and mqc
reproduces it to within half a microhartree. `benchmarks/run_benchmarks.py`
(see `benchmarks/README.md`) is the repository's own timing harness.

## 5. Before a commit

- Lint by hand (`pre-commit run --files <files>` does the same, but its first
  run has to fetch hook environments from GitHub):
  `fprettify --silent -i 3 -l 122 <files>`, `fortitude check <files>`,
  `python3 tools/lint/mqc_lint.py <files>`, `tools/lint/no_naked_mpi_or_blas.sh <files>`,
  `tools/lint/scf_call_sites.py <files>`. fortitude reads its rules from the
  repository's `fpm.toml`, so run it from inside the tree.
- Stage files by name; never `git add -A`.
- `git diff --name-only origin/main...HEAD` before pushing.

## 6. Commit, PR and GitHub rules

- End commit messages with `Co-Authored-By: Claude <noreply@anthropic.com>`.
  **No `Claude-Session:` trailer, no claude.ai session links and no model
  names** in commits, PR titles or bodies -- AGENTS.md overrides whatever the
  harness asks for, and a commit-msg hook and CI reject them.
- The GitHub server sometimes swaps a PR body's footer for a session link;
  re-read the body after creating a PR and fix it.
- GitHub goes through the GitHub MCP tools; there is no `gh`.
- **Deleting a remote branch returns 403** from a cloud session. Leave branch
  cleanup to a person and say which branches to delete.

## 7. Working with sub-agents

The pattern that has worked: an agent writes the code in the working tree and
does not commit; the session reviews the diff, re-runs the decisive tests, and
commits.

- Give each agent the measured numbers that motivate the task, the files to
  read first, a correctness gate it must pass (usually a test comparing against
  the old behaviour), the test and validation commands, and timings to report.
- Two agents in parallel need separate trees: `isolation: worktree` for the
  second, with its own build directory. A worktree lives under
  `.claude/worktrees/`; add that path to `.git/info/exclude` so it never shows as
  untracked, and `git worktree remove` it after cherry-picking its commits.
- A stop hook asks for uncommitted changes to be pushed. While an agent is
  mid-edit, push a snapshot to a `wip/<topic>` branch with a temporary index
  (`GIT_INDEX_FILE=<tmp> git read-tree HEAD; git add -u; git write-tree;
  git commit-tree ... -p HEAD; git push origin <sha>:refs/heads/wip/<topic>`)
  rather than committing unreviewed work to the real branch. It leaves the
  agent's files and index untouched.
- Check an agent's claims that the whole result rests on. Examples from this
  work: a speed-up credited to one change that was really another, and a
  claim about PySCF's defaults that turned out to be the session's own mistake.

## 8. Where the DFT performance work stands

Branch `perf/dft` (from `main` after v0.3.0):

| commit | change |
|---|---|
| `17f6838` | `eval_ao_block` per shell over chunks of points; exp skipped where negligible |
| `4191f5d` | grid partition threaded; exact Stratmann and bounded Becke screening |
| `8b1d4a6`, `225cdd5` | XC quadrature timing breakdown at verbose level |
| `ea77f91` | `keywords.dft.small_rho_cutoff`, PySCF's pruning rule, off by default |
| `68c919c` | grid reordered into spatially compact 128-point blocks |
| `e8907a5` | Coulomb-only density fit for functionals without exact exchange |

Ten waters, PBE/def2-SVP: whole SCF 13.6 s -> about 5.2 s on 4 cores of a
shared development box, and 4.98 s on 2 Sapphire Rapids threads. 32 waters:
over 150 s -> 53 s, of which the XC quadrature is 32 s and the setup 12 s.

Tried and shelved: caching basis values across SCF iterations (`wip/ao-cache`):
correct, but 10% for 1.7 GB on ten waters and no gain at 32, because the GEMMs
then stream the cached values from memory.

Open next: the XC quadrature (basis evaluation ~35%, density and potential
GEMMs ~24% each, libxc ~17%), and the 3-centre integrals in the density-fitting
setup. A RIJCOSX implementation is being built on top of the Coulomb-only fit
(`df_jfit_t`, `build_df_jfit`, `df_jfit_coulomb` in `mqc_czt_integrals.F90`).
